# Plan: browser end-to-end suite with `e2e` (phase 1 of the Void move)

Design: `.superpowers/specs/2026-10-31-void-solid-frontend-design.md`. Branch: `feat/e2e`.

The repository has no Playwright tests. Only two stale `.gitignore` lines remain. This phase adds a new suite on the `e2e` package. It is the safety net for the later phases (gate → dash → app → api on Void and Solid), so the tests must keep passing, unchanged, across those rewrites.

## Rules for the tests

- Assert on roles and visible text only. Do not import from `apps/*/src`, and add no test ids that name an implementation detail.
- Use deterministic locator steps only. Add no `agents` key, so the suite needs no model and no API key.
- Pin the locale to English (`en-US`), because dash and app render both English and Japanese.
- Run against the real local stack, not mocked routes, so the api phase is also covered.

## Package

- `packages/e2e` (`@fuda/e2e`, private). Pin `e2e@0.21.3` and `@e2e-dev/web@0.15.3`, the newest releases older than the 3-day `minimumReleaseAge`. Add `viem` for the seed signer.
- Hand-write `e2e.config.ts`; do not run `e2e init`, which writes agent, MCP and gateway files.
- Name the script `e2e`, not `test`, so the root `pnpm test` and the CI `package` step never start a browser. Add a root script: `"e2e": "pnpm --filter @fuda/e2e e2e"`.
- Set `E2E_TELEMETRY_DISABLED=1` in the script.
- In `.gitignore`, replace the Playwright lines with `.e2e/`.

## Stack

`packages/e2e/scripts/stack.ts` is the single `app.command` that all three targets share:

1. Create a fresh `--persist-to` directory under `packages/e2e/.e2e/state`, so the developer's `.wrangler/state` is never touched.
2. Apply the D1 migrations there.
3. Start `wrangler dev --env local` on a non-dev port with `--env-file packages/e2e/stack.env` (`USE_FAKE_CHAIN=1` only). An explicit `--env-file` makes wrangler skip `apps/api/.dev.vars`, so local secrets never reach the run. Override `API_BASE_URL` and `PUBLIC_BASE_URL` with `--var`.
4. Start the gate, dash and app Vite dev servers on non-dev ports, with `VITE_API_BASE_URL`, `VITE_APP_ORIGIN` and `VITE_RP_ID=localhost`.
5. Stop every child process on exit.

The runner waits on the api health route (`readyUrl`).

## Seed

`packages/e2e/tests/support/seed.ts` uses only public api calls, the way `apps/api/scripts/smoke-live.ts` does:

- Bearer right: `POST /v1/issue` (admin routes are open while `ADMIN_TOKEN` is unset).
- Venue and card: generate a throwaway EOA key, then call `/auth/challenge` and `/auth/verify` (EOA signatures verify offline), `POST /v1/issuers`, and `POST /v1/issuers/cards`.

## Coverage (smoke level)

- **gate**:
  - the scanner renders;
  - a pasted bearer QR shows an admit verdict;
  - the same QR again shows "already used";
  - garbage input shows the unreadable verdict;
  - dismissing a verdict returns to the scanner;
  - `?camera=off` shows the reader-only station.
- **app**:
  - the top page renders;
  - `/@<handle>` shows the seeded card;
  - `/@<handle>/home` shows the store display;
  - an unknown handle shows the missing-venue recovery.
- **dash**:
  - the sign-in screen renders;
  - admin-token sign-in with an empty token reaches the admin view, and issuing a right there shows its result.
  - Operator passkey sign-in goes through Base Account and is out of scope.
