# C2 CCIP-Read Transport Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship the B1-independent CCIP-Read transport that resolves the existing D1 ENS mirror through a signed ENSIP-10 gateway and a from-scratch verifier contract.

**Architecture:** A deep TypeScript gateway module owns DNS-wire decoding, supported record dispatch, stable/private lookup, response expiry, and the EIP-3668 signature envelope behind one interface. A Hono adapter exposes the standard POST gateway shape and admits only configured resolver senders. A dependency-light Solidity package supplies the matching ENSIP-10 resolver and executes contract tests in Hardhat's built-in Solidity runner.

**Tech Stack:** TypeScript 7, Cloudflare Workers/D1, Hono, Valibot, viem 2, Solidity 0.8.28, Hardhat 3

**Spec:** `docs/specs/ens-naming.md` and the user-supplied C2 stretch spec

## Global Constraints

- Use `issuer` in code, schema, and technical prose; `venue` remains UI copy only.
- A resolving name is never authority and never enters the Gate admission path.
- Do not copy code, specifications, or designs from another repository.
- Do not install or transitively rely on `@ensdomains/ccip-read-router`.
- Implement the standard EIP-3668 POST request/response shapes and ENSIP-10 `resolve(bytes,bytes)` interface.
- Bind every response signature to the resolver address, response expiry, full gateway request, and result.
- Private records allocate once only after the complete request and signer configuration have validated; they are never cached.
- Do not modify B1-owned issuer onboarding, issuance, delegation, or revocation flows.
- Do not pin a live ENSv2 address until an exact upstream commit and deployment namespace are selected.
- Follow strict TDD and commit each independently verified task.

**Files:**

- Create: `apps/api/src/ens/gateway.test.ts`

**Interfaces:**
- Consumes: `lookupEnsName()`, `allocateStealthResolution()`, a D1 `Db`, and a signing private key
- Produces: `resolveGatewayRequest(db, input): Promise<Hex | null>`
- Produces: exported resolver-service ABI and helpers used by route and cross-language tests

- [ ] **Step 1: Write failing codec and dispatch tests**

  Build literal DNS-wire fixtures and resolver calldata with viem. Assert that a
  stable issuer or member name answers both `addr(bytes32)` and
  `addr(bytes32,uint256)` for coin type 60, that the embedded node must equal the
  DNS namehash, and that unsupported selectors, coin types, malformed DNS names,
  malformed ABI, unknown names, and foreign parents return null without writes.

- [ ] **Step 2: Verify the focused tests fail for the missing module**

  Run: `pnpm --filter api exec vitest run src/ens/gateway.test.ts`

  Expected: FAIL because `src/ens/gateway.ts` is missing.

- [ ] **Step 3: Implement minimal request decoding and result dispatch**

  Decode only `resolve(bytes,bytes)`. Parse DNS-wire labels without compression,
  enforce the terminating root byte and 63-byte label limit, normalize through the
  existing name parser, check the resolver record's node against `namehash(name)`,
  and ABI-encode either an address or 20-byte multicoin value.

- [ ] **Step 4: Add failing signature and private-allocation tests**

  Assert the response tuple is `(bytes result,uint64 expires,bytes signature)`,
  the recovered signer matches a literal private key, the digest is
  `keccak256(0x1900 || resolver || uint64(expires) || keccak256(request) ||
  keccak256(result))`, the expiry is bounded by both a short response TTL and the
  name expiry, and consecutive private requests persist distinct counters and
  answers. Assert malformed signing/allocation secrets fail before allocation.

- [ ] **Step 5: Implement signing and private allocation**

  Validate both secrets, compute the final response expiry, allocate a private
  destination only after validation, sign the raw digest with viem's local account,
  and return the ABI-encoded tuple.

- [ ] **Step 6: Verify and commit the gateway module**

  Run: `pnpm --filter api exec vitest run src/ens/gateway.test.ts`

  Run: `pnpm check`

  Commit: `feat(api): sign ENS gateway responses`
